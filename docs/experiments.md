## 1. 我们实际要证明什么

把 Reviewer 的价值拆成三个强度递增的命题：

| 命题 | 内容 | 现有文献 |
| --- | --- | --- |
| **H1 功能命题** | 评价—反馈—纠错机制能改善检索或检索增强任务 | 证据较强 |
| **H2 学习命题** | 反馈可以更新检索策略，并跨 episode 累积 | 有支持 |
| **H3 拓扑命题** | 该机制**必须实现为独立上下文的 sidecar agent**，才拿得到收益 | **无直接证据** |

H1 与 H2 已由他人证明；把它们写进贡献是抢功。
**本项目的贡献只能建立在 H3 上**——因此 H3 是主命题，Reviewer 是主要消融目标。

由此确定叙事口径。不得写成：

> 我们提出一个独立上下文的 Reviewer，它提升了论文检索。

应写成：

> 我们提出一种独立上下文、可持久学习的 retrieval-audit sidecar，
> 并在等算力条件下系统检验它相对于 self-reflection、stateless critic
> 和等算力单 agent 的真实增益。

后者即使实验结论为负也仍然成立，前者不能。**可证伪性是这里的资产而不是负担。**

## 2. 文献证据的边界

### 2.1 正面证据支持什么、不支持什么

| 工作 | 报告结果 | 能支持 | 不能支持 |
| --- | --- | --- | --- |
| CRAG（arXiv 2401.15884） | PopQA 50.5 → 54.9；训练过的检索评价器准确率 84.3，高于提示式 ChatGPT 评价器 **[待核对]** | 训练过的独立 retrieval evaluator 能改善检索纠错 | 评价器需要是**有独立上下文的 agent** |
| Self-RAG（arXiv 2310.11511） | 去掉 Critic 后 PopQA 45.5 → 42.6，ASQA 32.1 → 18.1 **[待核对]** | critique 信号与基于 critique 的选择重要 | 推理期需要运行 sidecar——其 Critic 主要用于离线数据构造与蒸馏 |
| Reflexion（arXiv 2303.11366） | 带 Wikipedia 检索的 HotPotQA 相对基线约 +20%；反思比仅保留轨迹记忆额外 +8pt **[待核对]** | 分析失败轨迹并生成语言反馈可改善后续尝试 | Reviewer 必须**并发运行**，或独立上下文本身是收益来源 |
| PaSa（arXiv 2501.10120v2） | Table 7：去掉 Selector 作为 Crawler 的辅助奖励模型后，RealScholarQuery recall `0.6111 → 0.5148` **[实测]** | **在论文检索中**，独立相关性评估器可有效训练搜索策略 | Selector 是在线策略 Reviewer——它是 relevance / reward model |
| oh-my-pi | Advisor 使用独立模型与独立上下文，逐轮观察 Main 并注入建议 | 该交互形态在产品上可实现，能形成可见的协作体验 | 未见针对 Advisor 的独立 benchmark 或 matched-compute 消融 **[待核对]** |

### 2.2 PaSa 是最近的一条证据，但不是同一个命题

PaSa 的 Selector 是：

$$
\mathrm{Selector}(q, p) \rightarrow (\mathrm{relevance},\ \mathrm{reward})
$$

我们的 Reviewer 是：

$$
\mathrm{Reviewer}(\bar{\tau}_t,\ C^R_t) \rightarrow \text{search-policy advice}
$$

前者对**单篇论文**做二元相关性判断，是逐点的、可枚举的、有明确 ground truth 的。
后者要判断"下一步该换检索式、扩引文、补哪个子主题，还是停止"——
这是对**策略**的判断，作用面更大、反事实不可观测、也远更缺少直接实证。

PaSa 证明的是：独立评估信号能训练检索策略。这支持 H2，**不支持 H3**。

### 2.3 反向证据

两条必须正视：

- **等 token 预算下单 agent 常追平多 agent。** Tran & Kiela，*Single-Agent LLMs Outperform
  Multi-Agent Systems on Multi-Hop Reasoning Under Equal Thinking Token Budgets*
  （arXiv 2604.02460）在 Qwen3、DeepSeek-R1-Distill-Llama、Gemini 2.5 三个模型族上发现，
  推理 token 恒定时单 agent 一致地追平或超过多 agent；并指出既有评测中报告的多 agent
  优势多来自**未计入的算力与上下文效应**，而非架构本身。**[实测]**
- **弱 reviewer 会拖累强 main。** Wynn, Satija & Hadfield，*Talk Isn't Always Cheap:
  Understanding Failure Modes in Multi-Agent Debate*（arXiv 2509.05396）观察到模型
  频繁因同伴推理从正确答案改为错误答案，倾向于附和而非质疑有缺陷的论证，
  并将其归因于 sycophancy 与社会性从众。**[实测]**

结论：**"让另一个 agent 多说一次"不是稳定的增益来源。** 第一条直接质疑我们的架构前提，
第二条给出了负增益的具体机制。两条都必须在实验设计里被主动检验，而不是在讨论章节里被提一句。

## 3. 混淆变量清单

一次额外的 Reviewer 调用同时改变了至少七件事：

```text
1. 增加了生成 token
2. 增加了模型采样次数
3. 增加了重新阅读问题的机会
4. 可能使用了更强或不同的模型
5. 引入了新的提示词与评价目标
6. 扩大了总检索与计算预算
7. 最后才是：引入了独立上下文
```

因此，即便观察到

$$
\mathrm{Score}(\mathrm{Main} + \mathrm{Reviewer}) > \mathrm{Score}(\mathrm{Main})
$$

也**推不出**增益来自独立上下文。真实的分解是

$$
\mathrm{gain} = \underbrace{\text{extra compute} + \text{extra sampling}}_{\text{已被证明非零，见 2.3}} + \text{critic signal} + \text{context separation}
$$

M 轴的全部设计目的，就是把最后一项从前三项里剥出来。

## 4. 两条正交的消融轴

### 4.1 轴的划分对齐到两个时间尺度

架构里有两个时间尺度，消融轴必须跟着分：

| 轴 | 尺度 | 检验 | 其余尺度的处理 |
| --- | --- | --- | --- |
| **M 轴** | $t$（episode 内） | 在线拓扑：独立上下文是否不可约简 | $k$ 尺度更新**全程关闭** |
| **P 轴** | $k$（跨 episode） | 离线偏好：策略先验能否被学习 | M 配置**固定** |

**这个隔离是硬约束。** 若 M 轴的某一组带着 $k$ 尺度更新，它就和 P 轴的 P2/P3 重复，
两条轴同时动，任何差异都无法归因。P 轴定义见 `prototype.md` §6.5，本文不重复。

### 4.2 M 轴：在线拓扑（$k$ 更新关闭）

| 组 | 配置 | 检验的问题 |
| --- | --- | --- |
| M0 | Main only | 基线 |
| M1 | Main + 同上下文 self-reflection | 「多想一次」是否已经足够 |
| M2 | Main + stateless critic worker（无独立上下文、无跨步状态） | critic **功能**是否足够 |
| **M3** | Main + 独立上下文 Reviewer（本架构） | **context separation 是否有效** |
| M3g | M3 但关闭建议的运行时 gate | gate 是否在挡住负面建议（§2.3 第二条） |
| M3† | M3 但 Reviewer 可读 $C^M_t$ | **越界诊断上界**，见 §4.3 |
| M5 | Main + 与 M3 等量的额外 token，无 Reviewer | 增益是否只是额外算力（§2.3 第一条） |
| M6a | M3 但注入**来自另一 query** 的建议 | 建议**内容**是否被真正利用 |
| M6b | M3 但注入延迟 3 步的建议 | 建议的**时效**是否重要 |
| M6c | M3 但建议恒为形状合法的 `NOOP` | 被"打断"本身是否就有收益 |
| M7 | Reviewer 只展示给用户，不注入 Main | 区分 UX 收益与任务收益 |

M6a/b/c 是**安慰剂组**。它们回答一个 M0–M5 无法回答的问题：Main 究竟是在利用建议的语义，
还是仅仅因为被插入了一段额外文本而改变了采样轨迹。缺了这组，即使 M3 显著胜出，
机制解释仍然是空的。

### 4.3 M3† 的存在理由

按架构约定，Reviewer 只能读公开轨迹 $\bar\tau_t$（SearchState + EvidenceState），
读不到 $C^M_t$ 与思考块。**这是一个自缚手脚的测试**：如果 M3 输了，我们分不清是

- (a) sidecar 拓扑本身无价值，还是
- (b) $\bar\tau_t$ 作为审计视图信息量不足。

M3† 让 Reviewer 越界读 $C^M_t$，只作为诊断上界存在。

$$
\Delta_{\mathrm{trace}} = \mathrm{Score}(\mathrm{M3}^\dagger) - \mathrm{Score}(\mathrm{M3})
$$

$\Delta_{\mathrm{trace}}$ 大 ⇒ 是 (b)，公开轨迹的字段设计需要返工。
$\Delta_{\mathrm{trace}} \approx 0$ ⇒ 是 (a)，架构结论成立。

**M3† 永远不是可交付配置**——它破坏上下文非对称性，进而破坏 Reviewer 的独立性。
它只出现在诊断表里。

### 4.4 主结论量

$$
\Delta_{\mathrm{sidecar}} = \mathrm{Score}(\mathrm{M3}) - \max\{\mathrm{Score}(\mathrm{M1}),\ \mathrm{Score}(\mathrm{M2}),\ \mathrm{Score}(\mathrm{M5})\}
$$

减数是 $\max$ 而**不是** $\mathrm{Score}(\mathrm{M0})$。基线必须是最强的替代方案，不是空。
拿 M0 当基线是这类实验最常见的自欺方式。

其余诊断量：

```text
Δ_gate    = Score(M3)  - Score(M3g)     gate 的价值
Δ_content = Score(M3)  - Score(M6a/b/c) 建议内容是否被利用
Δ_trace   = Score(M3†) - Score(M3)      公开轨迹是否有损（诊断，非主张）
Δ_memory  = Score(P3)  - Score(P1)      持久偏好的价值（P 轴，prototype §6.5）
```

### 4.5 不做全交叉

$\mathrm{M} \times \mathrm{P} \times \mathrm{B} \times \mathrm{J}$ 全交叉不可行。执行顺序：

```text
阶段 1  B 轴 / J 轴          定住排序器与判别档位          （prototype §6.5）
阶段 2  M 轴（k 更新关闭）    在 阶段1 胜出的排序器上跑
阶段 3  P 轴                 在 阶段2 胜出的 M 配置上跑
```

若阶段 2 的结论是 $\mathrm{M2} \approx \mathrm{M3}$，则阶段 3 改在 **M2** 上重跑——
持久偏好的价值不应绑定在一个已被证伪的拓扑上。

## 5. 等算力协议

### 5.1 匹配什么、不匹配什么

| 量 | 处理 |
| --- | --- |
| 生成 token | **匹配**：M3 的 Main + Reviewer 之和 = M1 / M5 的单体量 |
| 检索 API 调用数 | **精确相等**（硬控制，见下） |
| 候选池大小、rerank 配置、judge 档位 | 固定 |
| Main 模型、temperature、采样次数、随机种子 | 固定 |
| wall-clock、美元成本 | **报告，不作为匹配轴** |

检索 API 调用数必须精确相等，理由：若 M3 比 M1 多发了检索请求，
比较的就是**召回量**而不是**策略质量**，而召回量的差异会淹没一切其它效应
——候选没进池子时排序器无法补救（`prototype.md` §6.5 同一条原则）。

wall-clock 不作为匹配轴，因为 Reviewer 可与 Main 并发，
把并发的延迟优势计入架构收益是偷换概念。它该出现在成本报告里，不在主张里。

### 5.2 不做单点比较，做预算前沿

**这是本套实验最重要的方法论选择。**

单点等算力比较可以被调参钓出来：在某一个预算档上把 M3 调好、把 M1 调差，
就能造出任意大的 $\Delta_{\mathrm{sidecar}}$。防御方式是对每个 arm 扫 3–4 个预算档，
画 score-vs-budget 曲线，主张必须是

> **整条前沿占优**，或至少在预先声明的目标预算区间内占优。

在预注册中写死目标预算区间，事后不得平移。

### 5.3 M1 的公平性问题

M1 的 self-reflection 消耗 Main 自己的上下文窗口，M3 不消耗。
所以在长轨迹上 M1 天然吃亏——但**这恰恰就是我们主张的机制**（抗 context saturation），
不能因此说匹配不公平。

不过必须**按轨迹长度分层报告**，否则无法区分「sidecar 有效」与「Main 上下文爆了」。
由此得到一个可预注册的机制预测：

> $\Delta_{\mathrm{sidecar}}$ 随轨迹长度单调增。

**若均值为正但该单调性不成立，机制解释被证伪**，主张必须改写——
此时收益来自别处，我们只是不知道来自哪里。

## 6. 报告什么（而不只是均值）

### 6.1 均值会骗人：介入率分解

$$
\Delta = p(\text{介入}) \times \mathbb{E}[\text{增益} \mid \text{介入}]
$$

必须报告这个分解。介入率 5% 的高增益 sidecar 与介入率 100% 的低增益 sidecar
是两个完全不同的组件，均值可能相同。

按 §9，$p(\text{介入})$ 是**被控变量**而不是自变量：我们不比较它的不同取值。
但它仍是必报量，且固定之后它承担的作用变了——用来验证两件事：

- **实际介入率是否落在设计意图上**。低介入率是配置意图，不是自动成立的事实；
  若实测值远高于或远低于设计值，说明触发条件写错了，该轮结果不可用。
- **退化检测**。若 Reviewer 学会恒发 `NOOP`，则 $\mathrm{M3} \equiv \mathrm{M0}$，
  命题被平凡地"证实"而没有任何内容。$\mathbb{E}[\text{增益} \mid \text{介入}]$
  必须在足够多的介入样本上估计——低介入率会直接压低这个样本量，
  它同时也是 §7 最小可检测效应估计的输入。

### 6.2 伤害率

$$
\mathrm{HarmRate} = \frac{\#\{\text{相对配对基线变差的 episode}\}}{\#\{\text{全部 episode}\}}
$$

均值为正、伤害率 30% 的组件不可交付——§2.3 的第二条正是这个失效模式。
在预注册中写死伤害率上限，超过即判定为不可交付，不论均值。

### 6.3 误差相关性

context separation 的机制假设是「独立上下文 ⇒ 独立错误」。这可以直接测：

$$
\rho_{\mathrm{err}} = \mathrm{corr}\bigl(\mathbb{1}[\text{Main 单独失败}],\ \mathbb{1}[\text{Reviewer 判定失败}]\bigr)
$$

若 $\rho_{\mathrm{err}} \to 1$，说明**同一模型的两个独立上下文并不产生独立错误**，
机制假设不成立。此时必须补跑跨模型变体（Reviewer 换用不同模型族），
否则无法区分「独立上下文有效」与「模型多样性有效」。**[待验证]**

### 6.4 分层

除总体外，按以下维度分层报告：查询类型（`prototype.md` §6.1 的分型）、
轨迹长度分桶（§5.3 的机制预测依赖它）、意图 profile、新论文与经典论文分桶。

## 7. 统计

- **配对设计**：同 query、同种子跨 arm，用配对差值而不是组间均值。
- **配对 bootstrap 置信区间**，不用 t 检验（检索指标非正态，K 截断使分布有质点）。
- **多种子**：每个 arm ≥ 3 个随机种子，报告种子间方差；
  单种子结果不得作为任何主张的依据。
- **最小可检测效应**：以当前 query 集规模，预先算出能检出多大的效应并写入预注册。
  参照量级：PaSa 的 Selector 消融是 9.63pt——这个量级可检出；
  1–2pt 的差异在百量级 query 上不可检出，**不得声称**。
- **多重比较**：M 轴有 10+ 组，但主命题只有一个（$\Delta_{\mathrm{sidecar}}$）。
  其余全部标注为次要分析；未做多重比较校正的次要结论不得进入主张。

## 8. 预注册的可证伪点

在跑实验之前写定，事后不得修改：

| 观察 | 结论 | 对架构的处置 |
| --- | --- | --- |
| $\Delta_{\mathrm{sidecar}} \le 0$ | H3 **在所采用的介入率下**不成立 | **Reviewer 降级为 worker / tool**，架构简化。这是可接受结论，不是失败；但结论必须带上 §9 的归因边界，不得写成无条件否定 |
| $\Delta_{\mathrm{sidecar}} > 0$ 但 $\Delta_{\mathrm{content}} \approx 0$ | 收益来自"被打断"而非建议内容 | 机制解释错误，主张须改写 |
| $\Delta_{\mathrm{sidecar}} > 0$ 但不随轨迹长度单调增 | 机制解释被证伪（§5.3） | 保留组件，撤回机制主张 |
| $\Delta_{\mathrm{trace}}$ 显著大 | 公开轨迹信息量不足 | 返工 $\bar\tau_t$ 的字段设计，重跑 M 轴 |
| $\mathrm{HarmRate}$ 超过预注册上限 | 组件不稳定 | 不可交付，不论均值 |
| 仅 M7 有收益 | Reviewer 是交互模块 | **不得包装成检索性能贡献** |
| $\Delta_{\mathrm{memory}} \le 0$ | 持久偏好不成立 | 退回单 episode，$k$ 尺度从架构中移除 |

同时沿用 `prototype.md` §6.5 已声明的一条：
若 P2 与 P3 均不优于 P1，「策略先验应当被学习而非被撰写」的主张不成立。

## 9. 在线 Reviewer 的触发策略：固定，不消融

**介入率不是本轮的消融变量。** 触发策略按实现期的实际考虑确定一次，
在 M 轴全部实验组中保持同一配置。

采取的方向是**低介入率**：Reviewer 只在少数事件上介入，默认沉默。
依据是 §2.3 的第二条——介入越频繁，附和与错误传播的暴露面越大；
在没有证据支持高频介入的前提下，低介入率是风险更小的默认。**[设计]**

由此产生三条约束：

1. **触发策略是被控变量，不是自变量。** M0–M7 共用同一份触发配置；
   若中途调整，此前跑过的组全部作废重跑，不得混用两份配置的结果。
2. **具体的触发事件集与阈值定义在 `prototype.md`**，不在本文。
   本文只声明「固定且低」这一属性。**缺口**：`prototype.md` 目前没有这一节，
   阶段 2 开跑之前必须补上——否则该配置不可复现，M 轴结果不可比。
3. **介入率仍是必报量**，见 §6.1。固定它意味着不比较不同取值，
   不意味着不观测实际取值——两者是不同的事。

代价要写清楚：固定介入率之后，若 $\Delta_{\mathrm{sidecar}} \le 0$，
**我们无法区分「sidecar 拓扑无价值」与「这一档介入率选错了」**。
这是本轮实验主动接受的归因边界，结论中必须如实声明，
不得事后补一档介入率来救结论——那是改口径。**[Risk]**

## 10. 执行顺序与规模

| 阶段 | 内容 | 前置 | 主要产出 |
| --- | --- | --- | --- |
| 0 | 回放数据集与判定缓存就绪 | `prototype.md` §4.3 / §5.2 | 可复现的离线评测台 |
| 1 | B 轴 / J 轴 | 阶段 0 | 冻结的排序器与判别档位 |
| 2 | M 轴 + 预算前沿（触发策略固定，见 §9） | 阶段 1 | $\Delta_{\mathrm{sidecar}}$ 及全部诊断量 |
| 3 | P 轴 | 阶段 2 | $\Delta_{\mathrm{memory}}$ |
| 4 | M7 用户研究 | 阶段 2 | UX 收益，与任务收益分开报告 |

阶段 0 是硬前置：**没有判定缓存就没有可复现的比较**，
因为 judge 的非确定性会淹没 M 轴上待测的效应量（`prototype.md` §4.3）。

阶段 4 需要真人被试与独立的测量工具，P0 大概率不做；
在此之前**不得**以任何形式主张 UX 收益。

## 11. 风险与缺口

1. **benchmark gold 若由 LLM 生成或校验**，用 LLM judge 排序会系统性虚高；
   judge-free 消融是强制项（`prototype.md` §6.5）。该风险与 M 轴叠加时更严重：
   若 Reviewer 与 gold 生成器同源，$\Delta_{\mathrm{sidecar}}$ 可能纯属同源偏倚。**[Risk]**
2. **Reviewer 与 Main 同模型族**时误差可能高度相关，见 §6.3。跨模型变体是应急预案，不是可选增强。
3. **低介入率的触发配置未在 prototype 定义**，见 §9 第 2 条。这是阶段 2 的开跑前置。
4. **介入率固定带来的归因边界**：负结论无法区分拓扑无效与介入率选错，见 §9 末段。**[Risk]**
5. **CRAG / Self-RAG / Reflexion / oh-my-pi 的数字尚未对照原文核实** **[待核对]**，
   进入论文前必须逐条核对；PaSa 与 §2.3 两条已核实 **[实测]**。
6. **算力预算**：M 轴 11 组 × 3 种子 × 4 预算档，
   即使去掉不需要交叉的组合仍是三位数量级的完整评测跑。
   开跑前需要按阶段 0 的缓存命中率重估成本，必要时先削预算档数而非削种子数
   ——种子数决定的是结论能不能成立，预算档数决定的只是前沿画得细不细。
